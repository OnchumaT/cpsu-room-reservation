# database — โครงสร้างฐานข้อมูล

| ไฟล์ / โฟลเดอร์ | คืออะไร |
|---|---|
| `schema.prisma` | **โครงสร้างฐานข้อมูลฉบับปัจจุบัน** (ตาราง, คอลัมน์, ความสัมพันธ์) — ดูไฟล์นี้ไฟล์เดียวก็รู้ว่าฐานข้อมูลตอนนี้หน้าตาเป็นอย่างไร |
| `migrations/` | **ประวัติการแก้ไขฐานข้อมูล** ทีละขั้น เรียงตามเวลา — Prisma ใช้รันกับฐานข้อมูลใหม่ให้ได้โครงสร้างเดียวกับ `schema.prisma` |
| `migrations/migration_lock.toml` | บอก Prisma ว่าใช้ฐานข้อมูล MySQL (ห้ามแก้) |

## วิธีอ่านชื่อโฟลเดอร์ migration

```
20261019080104_add_facility_request_not_done
└─────┬──────┘ └──────────────┬─────────────┘
 วันเวลาที่สร้าง (UTC)          สิ่งที่เปลี่ยน
 ปี ค.ศ. เดือน วัน ชม. นาที วินาที
 2026-10-19 08:01:04
```

> **ห้ามเปลี่ยนชื่อ ลบ หรือแก้ไฟล์ในโฟลเดอร์ migration ที่รันไปแล้ว**
> Prisma บันทึกชื่อโฟลเดอร์ที่รันแล้วไว้ในตาราง `_prisma_migrations` ของฐานข้อมูล
> ถ้าชื่อไม่ตรง Prisma จะเข้าใจว่าเป็น migration ใหม่ แล้วพยายามรันซ้ำหรือขอล้างฐานข้อมูล (ข้อมูลหาย)
> จะแก้โครงสร้างเพิ่ม ให้แก้ `schema.prisma` แล้วรัน `npm run prisma:migrate` ใน `backend/` เพื่อสร้างโฟลเดอร์ใหม่

## คำสั่งที่ใช้บ่อย (รันในโฟลเดอร์ `backend/`)

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run prisma:migrate` | สร้าง migration ใหม่จาก `schema.prisma` แล้วรันกับฐานข้อมูล **local** |
| `npm run prisma:deploy` | รัน migration ที่ยังค้างกับฐานข้อมูลใน `.env` (ไม่สร้างใหม่) |
| `npm run prisma:deploy:prod` | รัน migration ที่ยังค้างกับฐานข้อมูล **cloud** (`.env.production`) — ข้อมูลจริง ระวัง |
| `npm run prisma:studio` | เปิดหน้าเว็บดู/แก้ข้อมูลในฐานข้อมูล |
